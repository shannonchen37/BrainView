# BrainView v2.0

清华大学 iMoonLab 脑电数据分析系统。项目面向 OpenBCI Cyton 采集设备，提供 EEG 实时采集、数据流稳定化、信号预处理、注意力状态预测、视频刺激展示、受试者信息管理，以及 MRI/fMRI/DTI NIfTI 影像导入与脑电状态关联展示。

> 说明：本项目定位为实验数据采集与分析平台，不输出医学诊断结论；MRI/fMRI/DTI 模块用于影像数据管理、展示和与 EEG 状态的联合摘要。

## 核心功能

- OpenBCI Cyton 设备初始化、串口配置、BrainFlow 数据流接入
- 8 通道 EEG 实时采集、通道标准化、原始数据定期落盘
- package number 连续性检查、重复包跳过、小间隙丢包插值、断流重连
- EEG 实时滤波、5 秒环形显示缓冲、RMS 指标展示
- 120 点预测窗口 + 60 点步长的注意力预测缓冲
- CNN + LSTM 注意力分类模型加载、预测结果与概率曲线展示
- 受试者信息录入、视频刺激播放、EEG 波形监测、分析结果可视化
- MRI/fMRI/DTI NIfTI 数据导入、中间切片展示、影像元数据记录
- EEG 注意力状态与影像模态的联合分析摘要

## 技术栈

- Python 3.8+
- PySide6：桌面端图形界面、视频播放、菜单和对话框
- BrainFlow：OpenBCI Cyton 数据采集与数据文件写入
- PySerial：OpenBCI 串口发现与初始化指令下发
- PyQtGraph：多通道 EEG 实时波形与注意力趋势展示
- PyTorch：CNN + LSTM 注意力分类模型推理
- NumPy / SciPy / scikit-learn：数据缓冲、滤波、标准化和离线预处理
- nibabel：MRI/fMRI/DTI NIfTI 文件读取

## 工程实现细节

### 1. OpenBCI 设备接入

通过 PySerial 扫描 `usbserial` 串口、向 Cyton 板卡发送停止流、软重置、默认通道配置、8 通道增益配置和 250 Hz 采样率指令，解决了 OpenBCI 设备启动状态不一致、手动配置步骤分散的问题，实现了上位机软件内的一键设备初始化。

通过 BrainFlow `BoardShim(BoardIds.CYTON_BOARD, params)` 建立采集会话，并使用 `start_stream()` 启动数据流，解决了底层硬件协议和上层分析代码耦合的问题，实现了从 OpenBCI 硬件数据到 Python 数据矩阵的统一接入。

### 2. 实时采集与数据流稳定化

通过 `get_board_data(chunk_size)` 消费式读取 BrainFlow 缓冲区，解决了重复读取最新窗口导致样本重叠的问题，实现了每个 EEG 样本只进入处理链路一次。

通过读取 BrainFlow package number 通道并按 256 取模检查连续性，解决了串口传输中难以及时发现丢包、重复包和大间隙的问题，实现了数据流质量的在线监测。

通过对小于等于 8 个采样点的包间隙执行线性插值，对重复 package number 样本直接跳过，对较大间隙记录告警但不强行插值，解决了短时传输抖动造成的波形断裂和大间隙插值引入伪迹的问题，实现了更稳定的实时 EEG 输入。

通过在采集线程中维护 `received_samples`、`dropped_samples`、`recovered_samples`、`duplicate_samples` 和 `large_gaps` 统计，并随 `data_updated` 信号传给主界面，解决了实时传输质量不可见的问题，实现了 UI 和日志中的数据流质量反馈。

通过超过 3 秒无数据告警、连续无数据后重新初始化设备、恢复后重新 `start_stream()` 并重置包序号状态，解决了设备短暂断连后采集线程容易停滞的问题，实现了基本的断流恢复机制。

### 3. 显示缓冲与预测缓冲分离

通过将显示数据 `display_data` 和分类数据 `classification_data` 分流处理，解决了实时显示滤波和模型输入稳定性之间互相影响的问题，实现了“显示链路可滤波、预测链路可独立标准化”的双通路数据处理。

通过为 EEG 波形显示维护 5 秒长度的环形 `data_buffer`，解决了连续输入数据块长度不固定、刷新时容易跳变的问题，实现了 8 通道 EEG 波形的稳定滚动展示。

通过为注意力模型单独实现 `PredictionBuffer`，解决了实时 EEG 连续输入与模型固定窗口输入不匹配的问题，实现了面向实时推理的预测缓冲机制。

### 4. 预测缓冲机制

预测缓冲是当前实时注意力分析的核心：

1. `PredictionBuffer` 内部维护形状为 `(8, 120)` 的缓冲矩阵，对应 8 通道 EEG 和模型需要的 120 个采样点。
2. 主界面每次收到采集线程发来的 `(samples, 8)` 数据块后，按样本逐行写入预测缓冲。
3. 当 `write_index` 达到 120 时，复制当前窗口作为一次模型输入。
4. 窗口生成后，将后 60 个采样点搬移到缓冲区前半段，并把写入位置重置为 60。
5. 下一批数据再写入 60 个新点后，就能形成下一个 120 点窗口。

通过“120 点窗口 + 60 点步长”的滚动缓冲，解决了模型固定输入长度和实时数据连续到达之间的矛盾，实现了 50% 重叠的连续注意力预测。

在 250 Hz 实时采样率下，120 点窗口提供约 0.48 秒上下文，60 点步长约 0.24 秒输出一次预测结果；通过将最近 10 秒预测结果保存在 `attention_history` 和 `probability_history` 中，解决了单次预测缺乏趋势信息的问题，实现了注意力状态阶梯图和集中概率曲线的实时展示。

通过在模型推理前对每个通道执行 Z-score 标准化，并将数据 reshape 为 `(1, channels, window_size)`，解决了实时采集幅值漂移和模型输入格式不一致的问题，实现了实时 EEG 到注意力分类模型的稳定输入。

### 5. EEG 预处理与注意力分析

通过 BrainFlow `remove_environmental_noise(..., FIFTY)` 去除 50 Hz 工频干扰，解决了实验室环境中电源噪声影响波形可读性的问题，实现了更清晰的实时 EEG 展示。

通过 `detrend`、1 Hz 高通和 1-50 Hz 带通滤波，解决了基线漂移和低频/高频干扰混杂的问题，实现了面向状态观察的实时脑电预处理链路。

通过 CNN 提取 EEG 空间特征、LSTM 提取短时间序列特征，再用全连接层输出二分类结果，解决了人工规则难以刻画注意力状态的问题，实现了低注意力/高注意力的自动预测。

通过同时展示离散注意力状态和高注意力概率曲线，并添加 0.5 阈值参考线，解决了单一类别标签解释性弱的问题，实现了可观察趋势和置信度的注意力分析结果展示。

### 6. 图形化实验平台

通过 PySide6 将受试者信息录入、视频刺激播放、OpenBCI 采集控制、EEG 波形监测、注意力结果展示和日志状态整合到一个主窗口，解决了实验过程中信息分散、操作路径割裂的问题，实现了面向真实实验流程的一体化软件平台。

通过 `QMediaPlayer` 和 `QVideoWidget` 支持本地 `.mp4/.avi/.mov` 视频刺激播放，解决了脑电实验中刺激呈现与采集软件分离的问题，实现了“视频任务展示 + EEG 实时监测”的同步实验界面。

通过 `DataFilter.write_file` 将原始 EEG 数据按时间戳写入 `Recordings/Brainflow-RAW*.txt`，解决了实时实验数据难以追溯的问题，实现了后续离线复盘和模型调试所需的数据记录。

### 7. MRI/fMRI/DTI 数据展示与联合摘要

通过 nibabel 读取 `.nii/.nii.gz` 文件，并对 3D 数据提取中间切片、对 4D 数据提取第一帧，解决了 MRI/fMRI/DTI 数据无法直接在桌面 UI 中快速预览的问题，实现了脑影像数据的一键导入与展示。

通过记录影像文件名、原始维度、展示切片、强度均值、标准差、最小值和最大值，解决了单纯显示图片缺少数据上下文的问题，实现了影像数据的结构化管理。

通过将最近一次 EEG 注意力预测、预测概率、预测窗口数量和影像元数据合并为多模态摘要，解决了单一脑电信号难以与结构/功能影像数据协同查看的问题，实现了面向 EEG 与脑影像联合分析的数据管理与展示界面。

通过 MRI/fMRI/DTI 菜单生成当前模态与 EEG 状态的联合分析报告，解决了实验人员需要手动整理多模态状态的问题，实现了包含影像元数据、注意力状态和数据流质量的自动摘要。

## 运行方式

安装依赖：

```bash
pip install -r requirements.txt
```

启动程序：

```bash
python src/main.py
```

打包程序：

```bash
python build_tools/build.py
```

打包产物会生成在 `build_tools/dist` 目录中。

## 数据输出

- 实时采集数据：`Recordings/Brainflow-RAW*.txt`
- 注意力分类器示例输出：`attention_classifier/output/`
- 打包应用：`build_tools/dist/`
